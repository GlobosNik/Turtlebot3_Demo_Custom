 # TurtleBot3 ROS 2 Workspace

This repository is a ROS 2 workspace for developing, building, and running TurtleBot3 applications. It provides a workspace structure for robot simulation, navigation, teleoperation, sensor integration, and custom ROS 2 nodes.

## Prerequisites

- Ubuntu with a supported ROS 2 distribution installed
- ROS 2 desktop tools and build dependencies
- Git
- Gazebo or the simulator supported by your ROS 2 distribution, if simulation is required
- TurtleBot3 packages and a configured TurtleBot3 model

Source ROS 2 before using the workspace:

```bash
source /opt/ros/<ros2-distro>/setup.bash
```

Replace `<ros2-distro>` with the installed distribution, such as `humble` or `jazzy`.

## Workspace layout

```text
turtlebot3_ws/
├── src/       # ROS 2 packages and application source code
├── build/     # Colcon build artifacts (generated)
├── install/   # Installed packages and environment setup (generated)
└── log/       # Build and runtime logs (generated)
```

Only packages in `src/` should normally be maintained manually. The `build/`, `install/`, and `log/` directories are generated by `colcon` and can be removed when a clean build is needed.

## Setup

Clone or place the project in the workspace, then install dependencies and build it:

```bash
cd ~/turtlebot3_ws
source /opt/ros/$ROS_DISRO/setup.bash
rosdep update
rosdep install --from-paths src --ignore-src -r -y
colcon build --symlink-install
source install/setup.bash
```

The `--symlink-install` option makes Python and other supported source changes available without copying files into the install space.

## TurtleBot3 configuration

Set the robot model before launching TurtleBot3 nodes or simulations. Use the model appropriate for the installed robot or simulation assets:

```bash
export TURTLEBOT3_MODEL=burger
```

Common model values include `burger`, `waffle`, and `waffle_pi`. Add the export to `~/.bashrc` if it should persist across terminal sessions.

## Running the project

Open a new terminal for each independent ROS 2 process and source both environments:

```bash
source /opt/ros/$ROS_DISTRO/setup.bash
source ~/turtlebot3_ws/install/setup.bash
```

Launch files and executable names depend on the packages included in `src/`. Discover available packages and executables with:

```bash
ros2 pkg list
ros2 pkg executables
```

Typical workflows include:

```bash
# Inspect available launch files in a package
ros2 pkg prefix <package-name>

# Launch a package-specific application
ros2 launch <package-name> <launch-file>.py

# Run a package executable
ros2 run <package-name> <executable-name>
```

For a physical robot, ensure the computer and TurtleBot3 are on the same network and follow the robot's official setup, safety, and sensor-calibration instructions before enabling motion.

## Useful ROS 2 commands

```bash
ros2 node list
ros2 topic list
ros2 topic echo /cmd_vel
ros2 topic info /scan
ros2 service list
ros2 action list
```

Use `rqt_graph` or other ROS 2 introspection tools to inspect node and topic connections. Do not publish velocity commands to a physical robot unless the area is clear and an emergency stop is available.

## Rebuilding and cleaning

Rebuild after changing source files or package metadata:

```bash
colcon build --symlink-install
source install/setup.bash
```

If stale build artifacts cause errors, clean the generated directories and rebuild:

```bash
rm -rf build install log
colcon build --symlink-install
source install/setup.bash
```

## Troubleshooting

- **Package not found:** source the ROS 2 installation and workspace setup files in the current terminal.
- **Missing dependencies:** run `rosdep install --from-paths src --ignore-src -r -y` and rebuild.
- **No robot topics:** verify that the required launch process is running and that ROS 2 discovery is working across the network.
- **Simulator fails to start:** check that the simulator and TurtleBot3 packages match the installed ROS 2 distribution.
- **Permission or device errors:** verify USB, serial, network, and user permissions according to the hardware setup.

## Development guidelines

- Keep each ROS 2 package focused and document its nodes, parameters, topics, services, and actions.
- Use descriptive names and consistent coordinate-frame conventions.
- Test changes in simulation before deploying them to hardware.
- Keep generated build artifacts out of version control.
- Record the ROS 2 distribution, TurtleBot3 model, and launch command used for reproducibility.
